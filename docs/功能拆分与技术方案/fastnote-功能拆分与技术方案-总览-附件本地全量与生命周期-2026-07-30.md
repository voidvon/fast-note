## 4. 里程碑与发布建议

- M1 数据基础（P0）：Dexie v4、结构化引用解析、远端文件名映射、本地读取优先。
- M2 全量闭环（P0）：增量/Realtime 下载后附件水合、失败重试、同步完成度状态。
- M3 删除闭环（P0）：远端附件差集删除、本地延迟 GC、永久删除远端优先。
- M4 完整性（P1）：远端 ID 清单、全量审计、配额治理和历史数据修复。
- 上线策略：先只建立索引并下载，不执行自动删除；确认审计结果后再启用远端差集删除和本地 GC。
- 灰度/回滚：使用本地 metadata 开关分离 `hydrate`、`remote-prune`、`local-gc`。回滚时关闭删除类开关，保留 Dexie 新表和已下载 blob，不降级数据库版本。

## 5. 跨模块依赖与风险

- 依赖关系：`session` 建立用户作用域数据库 -> `sync-notes` 完成 note 冲突裁决 -> 附件引用对账 -> 附件下载队列 -> 本地完整性审计/GC。
- 关键风险：IndexedDB 物理容量不足；大附件导致首次全量耗时；当前 HTML 正则解析可能误判引用；PocketBase 新文件上传仍有两次正文回填的短暂中间态。
- 已确认决策：不新增账号附件总量限制；回收站 note 保留 30 天且继续持有附件；普通附件移除不另设 GC 宽限期；不做旧客户端兼容门禁。
- 提示策略：文本同步不等待附件下载；同步区域持续展示附件进度，首次全量完成提示一次，失败、离线或空间不足时保留可重试状态。
